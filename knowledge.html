核心判断

AI产品经理的贡献，不是“接了哪个模型”。

面试官更关心你解决了什么业务问题，为什么这样设计，以及如何证明方案有效。
部门做什么，我负责什么，目标和指标是什么，我做了哪些关键判断，最后拿到了什么结果。

这是所有项目讲述的共同骨架。模型选型、OCR、ASR 或 Prompt 都只能放在“关键判断”里，不能抢走产品主线。

业务背景

先说明部门职责、目标用户、原方案缺口和业务损失。

个人目标

明确你负责改善的指标，以及上线必须守住的风险边界。

产品动作

只讲能体现判断的动作，包括标准、数据、策略、流程和协作。

验证结果

区分离线指标、线上指标、业务收益和仍未解决的问题。

模型与系统评测

先定义“好”，再讨论模型好不好。

评测体系由业务目标、Rubric、数据集、指标和迭代机制共同组成。

四种评测方式

同一个产品通常需要组合使用，而不是只依赖一个总分。

业务目标→能力拆解→评测标准→样本与指标
Ground Truth Benchmark

有标准答案的数据集

适合分类、抽取、工具执行和可验证任务。优势是稳定可回归，风险是题目污染与覆盖不足。

Rubric Scoring

按维度评分

适合开放式输出。先定义正确性、完整性、安全性与风格边界，再由人或模型评分。

Pairwise Arena

两两对比

适合答案没有唯一标准的体验问题。对比哪一个更好，再累计偏好结果。

Online Experiment

真实业务验证

通过灰度、A/B或人工复核观察任务完成率、投诉率、成本与留存。

测试集不是“一批题”，而是一套分层资产。

构建时要覆盖高频正常场景、关键风险、历史失败、相似负样本与真实流量分布。训练、调参与最终验收必须隔离。

双人标注 + 仲裁 按场景与难度分层 固定版本与可追溯来源 防止测试集泄漏
Golden Set稳定、有明确 Ground Truth 的核心集，用于版本横向比较。
Challenge Set隐喻、跨模态、长尾和对抗样本，检验能力上限。
Regression Set历次 Bad Case 沉淀，防止修复新问题时旧问题复发。
Holdout Set开发阶段不可见，最终判断泛化能力和是否过拟合 Prompt。
Rolling Set从最新线上流量抽样，识别分布漂移和新型表达。

指标要按错误成本选择

指标回答的问题适用重点常见误区
Precision判为风险的内容有多少是真的误伤成本高、直接处置精度高不代表漏放少
Recall真实风险中有多少被找到前置召回、有人审兜底必须先有可信正样本分母
F1 / Macro-F1精度与召回是否平衡多分类与类别不均衡总分会掩盖关键切片
Task Success系统是否完成用户目标Agent与端到端链路只看最终答案会漏掉危险过程
Cost / Latency效果是否能以可接受成本上线大模型、实时交互离线效果好不等于可产品化
必须分清三个口径

“覆盖旧策略命中样本86.5%”不是模型召回率；“随机抽样准确率81.6%”也不能证明真实风险召回。面试时要主动说明分母和样本来源。

Agent 与 Harness

Agent 的产品能力，来自模型与运行系统的组合。

模型负责理解与决策，Harness 让它在真实环境中安全、稳定、可观察地执行。

上下文构建

系统指令、用户状态、业务知识和本轮任务如何被组织。

工具与接口

工具描述、参数约束、返回结构和失败信息是否便于模型理解。

编排与状态

任务拆解、依赖顺序、重试、暂停、恢复和长任务状态管理。

权限与沙箱

最小权限、高风险确认、隔离执行、预算和操作范围限制。

记忆与反馈

短期状态、长期偏好、结果校验和必要位置的 Reflection。

可观测与评测

记录工具调用、轨迹、耗时、Token、错误与最终业务结果。

Workflow

路径预先定义

适合规则清晰、低歧义、高稳定性任务。可控性强，灵活性较低。

Agent

动态选择路径

适合步骤无法穷举、需要工具调用和环境反馈的复杂任务。

Reflection

结果后的反馈回路

对已执行结果进行检查、纠错或重新规划，不等同于单次生成中的 CoT。

CoT

一次决策中的推理过程

产品评测应关注可观察证据与行动轨迹，不要求暴露模型内部思维链。

Agent评测为什么不同

同一个目标可能存在多条合理路径，因此既要评最终结果，也要评过程是否安全、有效和可恢复。

Code-based Grader规则、单元测试、状态检查、执行结果
Model-based Grader按 Rubric 判断正确性、覆盖度与风险
Human Grader处理主观体验、高风险边界与模型分歧
任务完成率工具选择正确率参数正确率恢复成功率越权率延迟与成本

具身智能与世界模型

机器人评测不能停在“视频看起来对”。

要把感知、语言落地、规划、控制和恢复拆开，再用真实任务成功率做端到端验收。
Perception

感知

目标、空间、状态和多视角信息是否识别正确。

Grounding

语言落地

是否把自然语言准确映射到对象、位置和动作。

Planning

规划决策

能否拆解任务、选择顺序并根据反馈重规划。

Control

操作控制

抓取、移动、放置的精度、稳定性与动作连续性。

Recovery

长程与恢复

多步骤任务中能否发现失败、恢复并安全结束。

世界模型评什么

世界模型的价值不是生成漂亮视频，而是预测环境如何变化，以及动作会如何改变未来状态。

输入 Observation + Action，输出可信的 Future State，并能服务训练、规划或安全验证。
可控性给定动作或条件后，未来是否按预期改变
物理一致性重力、碰撞、摩擦、遮挡和对象关系是否合理
时序一致性长时间生成中身份、位置和环境状态是否漂移
反事实覆盖能否生成稀有、危险和“如果发生”场景
下游有效性合成场景是否真正提升策略训练或安全发现能力
Sim-to-Real仿真结果与真实机器人或道路测试是否一致

智能座舱也用同样思路

先按模块评语音识别、意图、槽位、多轮上下文、车控、地图与多模态理解，再做端到端任务执行率、安全拦截、时延和用户接管评测。一个模型覆盖多个业务域，不代表只需要一个总指标。

快手社区治理

评论区氛围大模型识别

业务问题 → 评估标准 → 测试集 → Prompt → 结果

60秒口述

我在快手社区治理团队负责评论区氛围识别项目。原有治理主要判断单条评论，但我们发现两类缺口：一类是单条无害、聚集后形成风险，另一类是评论区把原视频语义重新改写。我的目标不是简单接一个大模型，而是定义什么叫“风险氛围”，并建立可验证、成本可控的识别链路。我先和业务侧明确类型、倾向、浓度等评估标准，再从审核问题、举报和线上样本中构建分层测试集，补充相似负样本与跨模态难例。随后围绕输入范围、Prompt和模型进行对照实验。我们发现Top15评论覆盖82.9%的曝光，之后边际收益低于2%，因此采用视频信息加Top15作为输入，并通过Bad Case归因持续迭代。最终目标场景准确率达到93%。这个项目让我理解到，AI产品经理的核心是把模糊风险转成清晰标准、可信数据和可上线的策略闭环。

指标应该这样说

82.9%
Top15评论的曝光覆盖，不是模型效果指标。
93%
目标场景准确率。面试前还需确认测试集规模、正负比例与置信区间。
58.91%
早期某类型召回口径，不可直接表述为“从58.91%提升到93%”。
F1 0.35
类型与浓度联合输出表现，说明多目标任务需要拆分验证。
2分钟展开结构
  1. 背景：现有系统默认评论区风险等于单条风险之和，无法发现聚集表达与语义重写。
  2. 目标：在控制推理成本和误伤的前提下，补齐上下文风险识别能力。
  3. 标准：定义氛围类型、倾向、浓度及单条证据，明确正例、反例与豁免边界。
  4. 数据：从历史问题、举报、审核样本和线上抽样构建固定集、挑战集与回归集，双人标注并仲裁。
  5. 实验：比较TopN、输入模态、Prompt版本和候选模型，用切片指标分析涉外冲突、历史影射和视频依赖。
  6. 结果：选择Top15与OCR方案，准确率达到93%；联合目标F1仍偏低，因此拆分任务继续验证。
评估标准具体怎么定？

先用真实案例做边界讨论，把“看起来不舒服”拆成可观察证据。例如是否存在同向聚集、是否依赖视频上下文、是否形成明确攻击对象、风险评论占比与曝光浓度。再用正例、相似负例和豁免例验证标注员能否稳定执行。如果一致率低，就继续改Rubric，而不是先怪模型。

测试集怎么构建？

正例来自历史重点问题、举报核实和专项审核；负例包含随机流量与语义相似但合规的难负例；再按涉政、网暴、浓度和输入依赖进行分层。固定集用于版本比较，挑战集放隐喻和跨模态难例，回归集沉淀每轮Bad Case，Holdout用于最终验收。

Prompt和模型怎么分开优化？

先选能力较强且稳定的模型作为参考基线，在同一模型上把Rubric和Prompt优化到相对稳定，再使用完全相同的输入和评分标准比较候选模型。否则模型差异会和Prompt质量混在一起，无法解释结果。

为什么产品经理不应重点讲OCR和ASR？

它们是成熟的输入能力，不是这个项目最核心的产品贡献。应重点讲为什么增加某类上下文、它解决哪一类漏放、带来多少增益和成本，以及你如何据此做产品取舍。

快手社区治理

自杀自残图评识别

多路召回 → 小模型精判 → 旧策略替代评估

60秒口述

这个项目的背景是线上连续出现多批自杀自残图片、图文组合和隐晦文本案例，原有策略与模型无法稳定召回和识别。我的任务是设计一套“多路召回加统一小模型精判”的新链路，同时盘点旧策略，判断哪些能力可以被新模型替代。召回层组合六类自杀风险信号、视频反圈、高危词和三个历史相似库通道，把候选量控制在每周169.6万以内。精判层先定义主体、意图、图文关系和豁免边界，再构建包含真实漏放、随机负样本和难负例的测试集。我推动了五轮Prompt迭代，新增七条核心规则，集中解决文本单独误触发、豁免翻案和主体误识别等十一类问题。新方案对旧策略命中样本的覆盖率为86.5%，随机抽样准确率为81.6%，压测上线后的准确率为82.37%。最终新模型可以替换旧的非图片模型部分，同时保留具有独特高精度价值的图片相似库。这个项目的关键不是“上了一个模型”，而是完成召回、精判、成本和策略替代的整体产品决策。

三个指标不能混用

169.6万/周
候选池调用量，用来验证成本与服务容量。
86.5%
新粗召对旧策略命中样本的覆盖率，不是真实风险召回率。
81.6%
前期随机抽样测试集准确率，需要同步说明抽样范围。
82.37%

2分钟展开结构
  1. 背景：多批真实漏放说明旧规则、相似库和模型之间存在覆盖断层，也缺少统一判断标准。
  2. 目标：扩大候选召回，用一个标准统一的小模型做精判，并评估旧策略的可替代范围。
  3. 盘点：逐项梳理旧策略的输入、命中对象、独特覆盖、精度、量级和处置方式，避免简单全量下线。
  4. 召回：组合文本风险信号、视频反圈、高危词和历史相似库，控制周调用量在预算内。
  5. 精判：建立主体、意图、图片含义、图文关系和豁免Rubric，用真实漏放与难负例迭代Prompt。
  6. 替代：分别比较新增召回、旧策略覆盖、真实召回、精度、成本和独特样本，最终替换非图片模型部分并保留高价值相似库。
真实召回率应该怎么测？

需要先建立独立的真实正样本分母，例如从审核确认、举报核实和线上随机抽样中获得Ground Truth，再看这些真实风险中有多少进入候选池、多少被精判命中。86.5%只能说明对旧系统命中的兼容程度，不能覆盖旧系统本来就漏掉的内容。

测试集如何保证不失真？

按图片、纯文本、图文组合、主体指向、求助表达、科普豁免和玩笑语境分层。正例保留真实线上分布，挑战集提高难例密度，两者不能混成一个“准确率”。标注采用双人独立判断、冲突仲裁，并记录样本来源与时间，便于回归和漂移分析。

如何判断小模型可以替代旧策略？

不是只看总体准确率，而是建立替代矩阵：旧策略覆盖率、独特样本损失、新增召回、误伤、时延、成本、稳定性和降级能力。只有当旧策略没有不可替代的高价值切片，并且新链路在目标流量上稳定，才进入灰度下线。

为什么选择小模型而不是更强的大模型？

这是高量级、边界相对可定义的分类任务。产品目标是在可接受精度下获得更低时延和成本。大模型可以用于建立效果上限、辅助难例分析和生成弱标注，但线上精判不一定需要最大模型。
