02 · WHY THIS PRODUCT

问题不在“不会写文案”，而在流程断裂。

PRD 从运营团队每天反复切换平台、手工换算时区和搬运数据出发，把需求收敛为一个最小闭环，而不是堆砌 AI 功能。

01

账号分散

国内外九个平台反复切换，账号、负责人和权限状态不可见。

02

排期易错

海外 10:00、国内 18:00，频率与冲突主要依赖人工检查。

03

素材返工

不同画幅、封面与体积要求重复处理，视频号封面还有 512KB 强校验。

04

发布不可追

批量发布若缺少预检、幂等与回执，容易误发、重发或部分失败。

05

复盘靠搬运

平台指标口径不同，周报难以关联主题、素材和后续动作。

03 · OPERATING LOOP

把一次运营任务拆成六个可验收节点。

研究

论坛痛点、受众、平台调性、历史数据与竞品信号。

规划

按账号、区域、产品线和频率生成跨平台内容日历。

生成

按平台分别生成脚本、Caption、Hashtag 与 CTA。

适配

检查素材、画幅、清晰度和封面体积，保留原文件。

发布

预检后进入 Outbox，保留人工确认、幂等键和平台回执。

复盘

统一指标口径，识别高潜主题并回写下一轮选题。

04 · SKILLS ARCHITECTURE

不是一条万能 Prompt，而是一组有边界的能力契约。

每个 Skill 都定义触发条件、输入、输出、硬性门禁和完成检查；总控只做分类与路由，避免把所有任务塞进一个不可控的长对话。

hiitio-social-ops-orchestrator

统一读取账号与排期规则，判断任务属于排期、文案、素材、发布、视频、竞品、分析还是预算，并调用最窄的专业 Skill；信息缺失时标记“待确认”，不自行编造。

social-calendar-planner跨平台排期与频率检查

应用国内/海外默认时段、2–3 次周更规则，检查账号冲突、缺素材和缺负责人。

social-copy-hashtag-writer平台化文案、标签与 CTA

按语言、受众、产品线和平台形态生成变体，并检查绝对化与无依据参数。

social-asset-adapter素材检查、裁剪与压缩

读取尺寸、格式、体积和时长；保留原件；对视频号封面执行小于 512KB 的硬门禁。

social-publish-preflight发布前完整性与风险检查

验证账号权限、字段、素材、时间、预算与人工确认，输出 ready / blocked / manual review。

social-scheduled-publisher安全发布任务与结果回执

定义 Outbox、幂等键、分平台状态、3 次重试与部分失败隔离；不在 Skill 内保存凭据。

social-budget-guard生成、调用与重试成本门禁

按任务估算图像、视频、API 与重试成本，在 80% 提醒、100% 阻断，并给出缩减方案。

social-video-generation-supervisor脚本—分镜—QA—导出

控制模型能力误判、画面漂移、水印、错误产品和无上限返工；视频必须人工确认后才进入发布。

social-competitor-trackerWatchlist 与 breakout 检测

根据曝光、互动、速度等信号标记高潜内容，只生成原创跟进方向，不复制竞品素材、Logo 或文案。

social-analytics-dashboard指标统一、Top/Weak 与周报

归一化跨平台字段，计算互动率，输出内容/素材表现和下一步动作；缺失数据保持缺失，不填假值。

FRIDAYPARTS → HIITIO

FridayParts 的后期制作让我识别到规模化后的真正风险：产品画错、危险操作、水印与小字失真、重复生成成本、能力误判和发布不可追踪。因此和诚版本新增了视频生成监督、预算门禁、预检与发布回执，而不是只做内容生成。

05 · HOW IT WAS BUILT

从运营痛点到可运行原型，我具体做了什么。

01

需求收敛

梳理九个平台、账号矩阵、国内外发布时段、内容频率、素材类型和视频号封面硬约束，输出内部 PRD 与需求补全表。

02

产品边界

把 MVP 收敛为统一日历、素材裁剪压缩、竞品爆款追踪和数据看板；API 接入前先用 Mock/CSV/Manual Package 验证闭环。

03

Skill 契约

为每项能力定义触发方式、输入输出、参考规则、执行脚本、硬门禁和 Definition of Done，再由总控进行最小路由。

04

交互原型

将能力映射为同一工作台的信息架构，设计日历、素材、账号、竞品、看板和预检模块，并用自包含 HTML 完成可操作演示。

05

测试验证

用真实素材与结构化样本验证排期、文案、压缩、预检、预算、竞品和分析链路；保留 JSON、HTML、报告和 warning 作为证据。

06

生产化设计

为未来 API 接入补充 OAuth 权限探测、Outbox、幂等、回执、部分失败隔离和重试策略，同时明确哪些能力仍需人工确认。
